### 2-3. 형태 규칙

| 규칙 | 내용 |
|---|---|
| 괘선 | 28px 간격 가로줄. 맨 위 56px은 노트의 인쇄 칸처럼 줄 없이 둔다. 모든 글줄과 세로 간격을 28px 배수에 맞춘다 |
| 여백 칸 | 왼쪽 40px은 노트 여백. **번호는 여백 칸에 적는다**(문항 번호, 목차의 1부~4부, 결과의 순위 1~3). 뒤로 가기 버튼도 여백 칸에 둔다 |
| 모서리 | 0~2px |
| 그림자 | 쓰지 않는다. 카드는 얇은 실선, 메모는 덧댄 종이와 테이프로만 구분한다 |
| 선택 표시 | 칸을 채우지 않고 **손으로 동그라미 친 듯한 SVG 테두리**(강조색 2px)를 그린다 |
| 가치 색 표시 | 가치 이름 아래에 **색연필 밑줄**(손그림 획 모양 마스크)을 긋는다. 형광펜 띠, 카드 왼쪽 색 띠는 쓰지 않는다 |
| 카드 | 종이 카드처럼 ±0.6° 안에서 살짝씩 기울인다(카드 고르기 화면만) |
| 붙인 메모 | 결과 화면에서 나침반과 "가장 오래 고민한 문항" 두 곳만 테이프를 붙이고 살짝 기울인다 |
| 바닥 고정 영역 | 위쪽 구분선 없이 종이 바탕 그대로 둔다 |

### 2-4. 진행도 (화면 맨 위)

- 한 줄로 만든다. **[뒤로 아이콘(여백 칸)] [다섯 칸 막대]** (단계 숫자는 아래 줄 "2단계 / 5"에만 쓴다). 끝낸 단계 칸은 강조색(연필 빨강)으로 물든다(D41).
- 막대는 4px 두께, 칸 사이 간격 4px, 직각이다. 채운 부분은 먹색, 빈 부분은 `--rule-strong`이다.
- 지난 단계 칸은 꽉 차 있고, 지금 단계 칸은 1단계에서는 답한 문항 수만큼, 2~5단계에서는 최소 개수에 가까워질수록 차오른다.
- 단계 번호("2단계 / 5")는 막대 아래 첫 글줄에 작게 쓴다.

### 2-5. 글꼴과 크기

- 제목과 큰 숫자는 **마루 부리**, 본문은 **Pretendard**를 쓴다. 숫자는 `tabular-nums`로 자릿수를 맞춘다.
- 두 글꼴 모두 OFL 라이선스다. npm 패키지(`@kfonts/maruburi`, `pretendard`)의 woff2 파일을 `next/font/local`로 셀프호스팅한다.
- 크기
  - 본문 15~16px. 입력 칸은 16px 이상으로 둔다(iOS가 입력 칸을 누를 때 자동 확대하지 않게).
  - 문항 문장 20px.
  - 섹션 제목 22px, 브랜드 44px.
- 한국어는 `word-break: keep-all`로 단어 중간에서 줄이 바뀌지 않게 한다.

### 2-6. 금지

- 이모지와 장식 기호(🔒 ◷ ◎ ✦ ✨)
- 인디고·보라 계열 색, 그라디언트, 둥근 카드와 그림자의 조합
- 카드 왼쪽 색 띠, 결과 항목이 하나씩 차례로 나타나는 애니메이션(카드 한 장이 내려앉는 움직임은 허용, §2-7)
- 가운데 정렬 히어로, "아이콘 + 제목 + 설명" 3열 기능 소개

### 2-7. 움직임 (5판, D27)

| 순간 | 움직임 | 길이 |
|---|---|---|
| 단계가 바뀔 때 | 아래에서 살짝 올라오며 나타남(페이드 + 10px) | 0.36초 |
| 단어를 고를 때 | 손그림 동그라미가 연필로 그리듯 이어짐, 누르는 순간 살짝 눌림(0.95배) | 0.42초 |
| 3단계 순위 | 순위 배지가 톡 튀어나옴 | 0.32초 |
| 최대 개수를 넘게 누를 때 | 그 단어와 "최대 n개" 안내가 좌우로 살짝 흔들림 | 0.3초 |
| 진행 막대 | 칸이 부드럽게 차오름 | 0.45초 |
| 결과로 넘어갈 때 | "고른 단어를 정리하고 있어요"와 연필 선 | 0.9초 |
| 결과 카드 | 메모 한 장이 기울며 내려앉고, 그림 선이 그려진 뒤 색연필 칠이 번짐 | 0.6초 / 1.4초 |
| 해석 받기 | AI 버튼 패널이 아래로 펼쳐짐 | 0.35초 |
| 모달 | 배경이 어두워지고 창이 살짝 커지며 나타남 | 0.28초 |

- 곡선은 `cubic-bezier(0.22, 1, 0.36, 1)`(빠르게 시작해 부드럽게 멈춤) 하나로 통일한다.
- `prefers-reduced-motion`이면 모든 움직임을 끈다.

### 2-8. PC 마우스 호버 (D36)

- `@media (hover: hover) and (pointer: fine)`에서만 적용한다. 휴대폰에서는 호버가 없다.
- 바뀌는 것은 배경색, 테두리색, 글자색뿐이다. 크기, 여백, 테두리 두께, 글자 굵기, 위치는 바뀌지 않는다.
  - 단어 칩·가치 카드: 테두리가 진해지고 바탕이 조금 밝아진다.
  - 문항 선택지: 라벨 뒤에 옅은 바탕이 깔린다.
  - 주 버튼: 강조색이 조금 진해진다. AI 버튼: 강조색으로 채워진다.
  - 글자 버튼·펼치기: 글자가 강조색으로 바뀐다.
- 고른 상태도 글자 굵기를 바꾸지 않고 손그림 동그라미로만 보여 준다. 굵기가 바뀌면 글자 폭이 달라져 옆 단어가 밀린다.
- PC 1280px E2E가 호버 전후로 모든 칩의 위치와 크기가 같은지 검사한다.

### 2-10. 숫자와 긴 글자 (D38)

- 숫자는 `src/lib/text/format.ts`로만 보여 준다: 머문 시간 "1분 12초"(600초 이상은 "10분 넘게"), 사람 수 "1,284 · 1.2만 · 128만 · 1.3억". 어떤 수든 12자를 넘지 않는다.
- 맨 위 줄 글자(날짜 등)는 한 줄을 넘지 않게 말줄임한다. 긴 글자는 칸 안에서 줄바꿈한다.
- 인라인 SVG 아이콘에는 width/height를 직접 넣는다. CSS가 늦게 오거나 빠져도 아이콘이 화면을 덮지 않는다.

### 2-9. 배경음 (D34)

- [시작하기]를 누를 때부터 재생한다(브라우저 자동 재생 정책상 사용자 조작 뒤에만 가능).
- 모든 화면 **오른쪽 아래 엄지 영역**에 36px 동그라미 버튼(스피커 아이콘, fixed). 바닥 버튼 영역 높이만큼 위로 올려 겹치지 않는다. 켜져 있으면 음파와 먹색, 꺼져 있으면 사선과 회색. 끈 선택은 이 브라우저에 기억한다(D53).
- 소리 크기 0.35, 1.2초에 걸쳐 커지고 0.4초에 걸쳐 작아진다. 탭이 숨겨지면 멈춘다.

## 3. 레이아웃 원칙 (모바일 우선)

- 기준 폭은 360px이다. 데스크톱에서도 가운데 한 열(최대 480px)로 보여 준다. 휴대폰 화면을 그대로 크게 쓰는 방식이다.
- **엄지 영역**: 주 버튼은 화면 아래 고정 영역에, 단계 제목과 안내는 위쪽에 둔다.
- 바닥 고정 버튼에 가려지지 않게 `html { scroll-padding-bottom: 120px }`을 둔다(키보드 초점 이동 포함).
- 주 버튼은 화면 아래 고정 영역에 두고, iPhone 홈 바 영역(safe-area)만큼 띄운다.
- 누르는 대상은 높이 48px 이상, 간격 8px 이상이다.
- 화면 높이는 `100dvh` 기준으로 잡는다. 주소창이 접히고 펴져도 레이아웃이 튀지 않게 한다.

## 4. 화면별 설계 (5판)

이전 판의 문항 화면, 부 소개 카드, 다시 보기, 복사 안내 시트 설계는 git 기록에 남긴다.

### 4-1. 시작 `/`

- 맨 위 No. / Date. 인쇄 칸, 브랜드 "마음결", 한 줄 소개 "단어 몇 개로 3분 만에 적어 보는 나의 성격과 가치".
- 목차: 다섯 단계 이름과 문항·고를 개수를 점선으로 잇는다(여백 칸에 1~5). 360×740에서 스크롤 없이 들어온다.
- 안내 세 줄: 결과 카드와 AI 해석, 브라우저 안에서만 처리, 진단이 아님.
- 맨 위 줄 Date 오른쪽의 "?" 버튼(메인에서만) → "마음결에 대해" 모달(D54, D56, D60): 모달 안쪽 머리줄에 인덱스 탭 [마음결] [만든 사람]. 마음결 탭은 한 문단 소개 + 근거 + 한계, 만든 사람 탭은 괘선 메모 카드(이름·소개·손글씨 Contact)와 맨 아래 "고마운 것들" 각주. 아래 화면은 밀리지 않는다.
- 바닥 버튼: 늘 [시작하기] 하나. 누르면 새로 시작해 `/test/personality`로 간다(D39).

### 4-2a. 평소의 나 `/test` 1단계 (5지선다, D28)

```
┌──────────────────────────┐
│ ‹  ▬─── ─── ─── ─── ───  1/5 │
│ 1단계 / 5 · 평소의 나        │
│ 3 / 10                     │ ← 지금 문항 번호(마루 부리)
│ 정돈되고 질서 있는 게 좋아요.  │ ← 21px 굵게, 줄 길이 고르게
│                            │
│ 1  전혀 아니에요             │
│ 2 (아닌 편이에요)            │ ← 고르면 손그림 동그라미, 0.28초 뒤 다음 문항
│ 3  보통이에요               │
│ 4  그런 편이에요             │
│ 5  정말 그래요              │
└──────────────────────────┘
```

- 고르면 자동으로 넘어가고, 넘어가는 동안 두 번 눌러 건너뛰는 일을 막는다.

## 6. 문구 원칙

- **모든 문장을 같은 결의 자연스러운 해요체로 쓴다**(D14). 화면 안내, 문항, 선택지, 결과, 복사 프롬프트가 모두 해당한다.
  - 문항 예: "모임에서 분위기를 띄우는 편이에요." / "이 사람은 위험을 감수하는 걸 좋아해요."
  - 선택지 예: "전혀 아니에요 … 정말 그래요", "전혀 나 같지 않아요 … 정말 나 같아요"
- 말하듯 쓴다. 딱딱한 문어체("~한다", "~것이다")와 번역투("~하는 것이 중요하다")를 피하고 "~하는 게 중요해요"처럼 쓴다.
- 조사 병기("와(과)", "은(는)")를 쓰지 않는다. 받침에 맞는 조사는 `src/lib/text/josa.ts`로 붙인다.
- 판단하는 말을 쓰지 않는다. "좋다/나쁘다", "부족하다", "문제" 같은 표현을 피한다.
- 진단이나 유형처럼 들리는 말을 쓰지 않는다. "~형", "~성향 판정", "정상 범위" 등.
- 숫자보다 의미를 앞에 둔다. 예: "높은 편 (3.8)".
- 위기 안내 문구는 쓰지 않는다(D6).

## 7. 접근성

- 색 대비 AA, 모든 상호작용 요소에 키보드 포커스 링을 표시한다.
- 리커트는 `role="radiogroup"`, 카드는 `aria-pressed` 토글로 만든다.
- 진행 상황은 `aria-live="polite"`로 알린다.
- 나침반과 막대 그림에는 같은 내용을 담은 텍스트 대체 설명을 단다.
- 애니메이션은 `prefers-reduced-motion`을 존중한다.
- 글자를 200% 키워도 레이아웃이 깨지지 않게 한다.

### 2-11. 노트 인쇄 칸과 손글씨 날짜 (D42)

- 메인 화면 맨 위: "No. ____   Date. 〈손글씨 날짜〉". 날짜는 브라우저에서 읽은 오늘 날짜(예: 2026. 10. 20)를 나눔손글씨 펜으로, 살짝 기울여 밑줄 위에 적는다.
- 결과 화면 맨 위: 왼쪽 "마음결", 오른쪽 "Date. 〈테스트한 날짜〉"(같은 손글씨).
