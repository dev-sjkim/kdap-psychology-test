## 0. 설계 원칙

1. **짧고 재미있게.** 3분 안팎의 가벼운 자기 이해 활동이다. 1단계는 짧은 5지선다 10문항, 2~5단계는 마음 가는 단어를 여러 개 고르고 덜어내는 방식으로 섞어서 지루하지 않게 한다. 모든 화면은 스크롤 없이 한 화면에 들어온다(D31).
2. **근거는 가볍게, 해석은 정성적으로.** 성격은 검증 척도(Mini-IPIP)의 문항을, 가치는 이론(Schwartz)을 참고한 단어를 쓰되(§2), 결과는 점수가 아니라 기울기와 고른 단어로 정리한다. 검증된 척도가 아니라는 점을 시작 화면, 결과, 프롬프트에 밝힌다.
3. **결과물은 두 가지다(D18, D32).**

   | 결과물 | 구분 | 내용 |
   |---|---|---|
   | 결과 카드 | 필수 | 결과 화면 맨 위 그림 카드 한 장(§5). 상세는 [자세히 보기] |
   | 해석 프롬프트 | 필수 | 복사해서 자기 LLM에 붙여 넣는 글(§6). "# 마음결 · 날짜의 나" 제목 아래 8개 항목으로 답을 받는다 |

   - 그림 프롬프트는 7판에서 뺐다(D32).

   - 다시 보기와 저장 기능은 없다(D22). 복사한 글을 보관하려면 사용자가 메모장 등에 직접 붙여 둔다.
4. **진단하지 않는다.** 병명, 임상 용어, 유형 판정, 타인 비교를 쓰지 않는다. 결과 카드 그림에 이름을 붙이지 않는다. 위기 안내 문구는 넣지 않는다(D6).
5. **서버가 없다.** 모든 계산은 브라우저 안에서 한다. 고른 단어는 어디에도 전송·저장하지 않는다(배포 A 유형).

## 1. 화면 흐름

```
[시작 /] ─▶ [테스트 /test/<단계>] ──────────────────────────▶ [결과 /result]
              1 평소의 나          5지선다 20문항(한 화면에 한 문항)   ├ (0.9초) 고른 단어를 정리하고 있어요
              2 마음이 끌리는 단어   40개 중 7개                     ├ 프로필 카드 + 한 줄 통찰 (+ [자세히 보기])
              3 끝까지 남길 단어     ②의 7개 중 3개, 누른 순서=순위     ├ [AI에게 해석 받기] → 복사 + AI 버튼
              4 요즘의 나           12개 중 1~3개                   └ [처음부터 다시 하기] (두 번 눌러 실행)
              5 비워 내고 싶은 것    12개 중 1~2개 (D57)
              6 더 키우고 싶은 힘    가치 카드 10장 중 1~2개
```

- **주소(D39)**: 단계마다 `/test/personality` → `/test/values` → `/test/narrow` → `/test/now` → `/test/grow`. 메인 화면의 [시작하기]는 늘 새로 시작한다. 앞 단계를 마치지 않고 뒤 단계 주소로 오면 아직 안 끝낸 첫 단계로 돌려보낸다. 브라우저 뒤로가기로 오갈 수 있다.
- 1단계는 답을 고르면 동그라미가 그려지고 0.28초 뒤 다음 문항으로 넘어간다. 이동은 문항 번호 양옆의 "‹ 3 / 10 ›" 하나로만 한다(첫 문항의 ‹는 처음 화면으로). 1단계에는 맨 위 뒤로 화살표가 없다(D45).
- 2~5단계 바닥은 [다음] 하나이고, 뒤로 가기는 맨 위 화살표가 맡는다.
- 배경음은 [시작하기]를 누를 때부터 재생하고, 모든 화면 왼쪽 여백 칸의 동그라미 버튼으로 켜고 끈다(D34, D42).
- 2~5단계는 화면 한 장이다. 최소 개수를 채우면 [다음]이 켜지고, 최대 개수를 넘게 누르면 막고 살짝 흔들며 "최대 n개까지"를 0.48초 보여 준다.
- 단어 순서는 시작할 때마다 섞는다(2·5단계). 3단계는 2단계에서 고른 순서 그대로 보여 준다. 2단계에서 뺀 단어는 3단계에서도 빠진다.
- 진행 중 상태는 sessionStorage에만 둔다. 새로고침해도 이어지고, 탭을 닫으면 사라진다.

## 2. 문항, 단어, 근거

| 단계 | 내용 | 근거 |
|---|---|---|
| 1 평소의 나 | **Mini-IPIP 20문항 원판**(`src/data/likert.ts`). 특성(외향성, 친화성, 성실성, 정서 민감성, 개방성)마다 4문항. 선택지 "전혀 아니에요 … 정말 그래요" | Donnellan et al. (2006). IPIP 문항은 퍼블릭 도메인. 한국어판 검증·규준이 없어 기울기로만 쓴다(D50) |
| 2·3 가치 단어 | Schwartz 10가지 가치마다 **4개씩, 40개**(`src/data/words.ts`), 모두 3자 이하 | Schwartz (1992, 2012). 고르고 덜어내는 방식은 Personal Values Card Sort(Miller et al., 2001) 아이디어 |
| 5 비워 내고 싶은 것 | 일상의 무게 12개, 각각 "덜어 내면 자리가 생기는 가치"와 짝(D57) | 임상 증상 단어는 쓰지 않는다(D6) |
| 4 요즘의 나 | 기분 단어 12개 | 점수를 매기지 않는 가벼운 체크. 임상 증상 단어는 쓰지 않는다 |
| 5 더 키우고 싶은 힘 | 10가지 가치 카드 | `src/data/values.ts` |

## 3. 결과 정리 규칙 (`src/lib/analysis/analyze.ts`, 순수 함수)

| 대상 | 규칙 |
|---|---|
| 성격 기울기 | 특성마다 네 문항 평균(역방향은 6 − 응답). 3.75 이상이면 높은 쪽, 2.25 이하면 낮은 쪽, 그 사이는 "상황에 따라 달라지는 편". 3에서 1.25 이상 떨어지면 "뚜렷함"(strong). 카드 그래프용 비율 = (평균 − 1) / 4 |
| 나의 결(카드) | 높은 쪽·낮은 쪽인 특성 중 3에서 가장 멀리 떨어진 2개 |
| 가치 순서 | 남긴 단어 1·2·3순위에 3·2·1점, 내려놓은 단어에 0.5점. 같은 점수면 더 높은 순위로 남긴 가치, 그다음 정의 순서 |
| 결과 카드 | 1순위로 남긴 단어의 가치(D26) |
| 눈여겨볼 연결(patterns) | ① **기질 × 1순위 가치**(개방성↔변화 개방, 성실성↔보존, 친화성↔자기초월, 외향성↔자기고양; 맞물림/엇갈림) ② 남긴 세 단어 중 같은 가치가 2개 이상 ③ 남긴 가치 중 서로 반대 방향인 쌍 ④ 비우고 싶은 것의 짝 가치가 남긴 가치/키우고 싶은 힘과 같음 ⑤ 키우고 싶은 힘이 남긴 가치에 없음/있음 ⑥ 내려놓은 단어의 가치를 다시 고름. 최대 5개. **첫 항목이 카드의 한 줄 통찰(headline, D55)** |
| 망설임 | 가장 오래 머문 단계, 골랐다가 뺀 단어. 재미로 보는 참고 정보 |

## 5. 결과 화면

### 5-1. 프로필 카드 (`ResultCard`, D51)

글자를 최소화하고 그래프로 사람을 표현한다. 모든 글자는 2~7자 단어라 어떤 결과에서도 줄이 깨지지 않는다.

| 자리 | 내용 | 만드는 법 |
|---|---|---|
| 왼쪽 위 | **성격 오각형 그래프**(`ProfileRadar`). 축 이름은 2자(외향·친화·성실·민감·개방), 가운데 점선 오각형은 척도 중간(3점) | 특성별 비율 (평균 − 1) / 4. 선은 그려지듯 나타나고 점이 뒤따른다 |
| 오른쪽 위 | 1순위 가치의 상징 그림(작게, 64px) | 아래 표의 10종 |
| 지키는 가치 | 끝까지 남긴 3개 막대. 1·2·3순위 길이 100·72·48%, 색은 가치의 상위 차원 | `values.kept` |
| 요즘 | 기분 칩 1~3개 | `now` |
| 키우고 싶은 | 가치 이름(색연필 밑줄) 1~2개 | `grow` |
| 안내 | "유형이나 점수가 아니라, 응답이 기운 방향을 그린 거예요." | |

- 카드에는 점수 숫자를 넣지 않는다. 긴 풀이는 LLM 해석이 맡고, 해석 프롬프트는 카드의 다섯 특성을 그대로 설명한다.
- 360×740 화면에서 카드와 [AI에게 해석 받기]가 스크롤 없이 함께 보인다(E2E).

| 가치 | 그림 |
|---|---|
| 자기주도 | 내가 접어 날린 종이비행기 |
| 새로움 | 처음 보는 길 위로 떠오르는 열기구 |
| 즐거움 | 햇살 아래 펼친 소풍 돗자리 |
| 성취 | 산꼭대기에 꽂은 작은 깃발 |
| 영향력 | 배의 키(조타륜) |
| 안정 | 창에 불이 켜진 작은 집 |
| 규범 | 가지런히 놓인 연필 세 자루 |
| 전통 | 나이테가 보이는 큰 나무 |
| 배려 | 옆으로 기울여 씌워 준 우산 |
| 공존 | 여러 종류의 꽃이 함께 핀 화단 |

### 5-2. 자세히 보기 (`ResultDetails`)

눈여겨볼 점(patterns), 평소의 나(특성별 기울기), 끝까지 남긴 가치 1~3순위와 정의, 내려놓은 단어, 요즘과 앞으로, 고르는 동안(가장 오래 머문 단계, 골랐다가 뺀 단어), "어떻게 만들었나요?"(한계와 참고 문헌).

### 5-3. 해석 받기 (`AskAi`, D25·D30)

1. [AI에게 해석 받기]를 누르면 해석 프롬프트를 복사한다.
2. 그 버튼 자리에 "복사했어요. 쓰는 AI를 누르고, 대화창에 붙여 넣어 보내 주세요." 한 줄과 ChatGPT · Gemini · Claude 버튼, "휴대폰은 길게 눌러 붙여넣기, PC는 Ctrl+V. [다시 복사]" 한 줄이 나타난다. 큰 버튼은 없애서 바닥 영역이 결과를 가리지 않게 한다.
3. AI 버튼을 누르면 새 창으로 열고, 누르는 순간 해석 프롬프트를 한 번 더 복사한다(그사이 다른 것을 복사했어도 안전).
4. 복사가 막히면 같은 자리에 프롬프트 전문(읽기 전용)과 [텍스트 파일로 저장]을 보여 준다. 인앱 브라우저면 "다른 브라우저로 열기"를 안내한다.

- 복사와 새 탭 열기를 한 번의 탭으로 합치지 않는다. 새 탭으로 초점이 넘어가면 브라우저가 클립보드 쓰기를 막을 수 있다.
- AI 서비스 주소에 프롬프트를 쿼리로 미리 채우지 않는다. 길이가 길어 잘리고 방문 기록에 남는다.

## 6. 해석 프롬프트

### 6-1. 원칙 (D19 유지)

- 복사 전용이다. 사람이 읽기 좋은지보다 LLM이 잘못 읽지 않는지를 기준으로 만든다.
- 데이터를 앞에, 지시를 맨 끝에 둔다. `<result>`, `<about_test>`, `<rules>`, `<answer_format>` 태그로 나눈다.
- 데이터는 들여쓰기 없는 JSON, 키는 영어 snake_case, 값은 한국어.
- 사용자가 자기 이름으로 보내는 1인칭 해요체.
- 단어 id, 밀리초 기록, 섞은 순서, 앱 버전은 넣지 않는다.

### 6-2. 해석용 데이터 `PromptData` (version 5, `buildPromptData`)

전체 구조는 `docs/prompt-data-schema.json`이 기준이다(`npm run schema`로 만든다). 예시:

```json
{
  "version": 5,
  "date": "2026-10-20",
```

### 6-3. 답변 형식 (v7, D59 · D74 · D75 · D76)

- 첫 문단에서 "성격심리와 가치 연구를 잘 아는 사람이 저를 오래 본 친구처럼, 따뜻하지만 솔직하게" 풀어 달라고 하고, 읽는 사람이 "맞아, 나 이래" 하고 고개를 끄덕일 만큼 차근차근 풀어 써 달라고 한다.
- `<about_test>`에서 데이터마다 읽는 법을 준다. clear_answers는 평소 모습의 가장 확실한 근거, kept_values는 word로 말하기, 중간 특성은 빼기, 카드 그림은 답에 쓰지 않기.
- 순서는 Finn의 치료적 평가 순서(이미 아는 모습 → 넓히는 해석 → 받아들이기 어려운 이야기는 뒤에 한 번)를 따른다.
- 답변 맨 위에 `# 마음결 · 2026년 10월 20일의 나` 제목 한 줄, 그 아래 7개 항목. 전체 2,800자 안팎.

| # | 항목 | 분량과 지시 |
|---|---|---|
| 1 | 한 줄 타이틀 | 글 전체를 꿰는 중심 줄기, "~하는 사람" 꼴 40자 안쪽. 가장 지키는 단어와 성격을 함께, 따옴표·카드 그림·추측 표현 없이 |
| 2 | 이런 사람이에요 | 두 문단 7~9문장씩. 첫 문단은 clear_answers와 뚜렷한 성격으로 평소 모습, 둘째 문단은 headline에서 출발해 그렇게 움직이는 이유를 지키려는 단어로, 겉모습과 속마음을 함께 |
| 3 | 이런 순간의 나 | 4~6문장. 2번의 모습이 드러나는 평범한 상황 두세 개를 "~할 때는 ~해요"로, 그때의 속마음, 마지막에 할 법한 말 한 줄 |
| 4 | 자주 부딪히는 지점 | 5~6문장. 앞의 강점이 짐이 되는 상황(같은 뿌리의 대가), 성격과 단어가 어긋나는 이유, 내려놓은 단어의 아쉬움, 조심할 점으로 맺기 |
| 5 | 비우고 싶은 것과 키우고 싶은 것 | 5~6문장. 덜 것이 왜 유독 무거운지 먼저 알아봐 주고(덮지 않기), 덜면 되찾는 것, 키울 힘이 왜 필요한지를 요즘 기분과 함께 |
| 6 | 이번 주 작은 한 걸음 | "- " 두 줄, 10분 행동. 앞 줄은 비움, 뒷줄은 키울 힘 |
| 7 | 응원 한마디 | 2번의 모습을 다시 짚으며 1번의 중심 줄기로 맺는 2~3문장 |

규칙 13가지(`PROMPT_RULES`):
1. 데이터만 근거로 쓴다.
2. 글의 주인공은 사람이다. 단어끼리의 관계를 설명하지 않고, 문단 앞쪽에서 저에 대한 판단을 분명히 말한다.
3. 풀어 쓴다: 판단 → 이유(성격과 지키려는 단어에서) → 평소 행동 → 속마음을 "~해서·그래서·그러다 보니"로 잇고, "~할 때는 ~해요"처럼 상황을 붙인다.
4. 가치 단어와 덜어 낼 것은 이유를 밝힐 때 작은따옴표로 부르되 문단마다 한두 개. 기분은 따옴표 없이.
5. 다른 답을 한 사람에게도 맞을 말은 빼고 조합에서 나오는 말을 쓴다. 강점은 같은 성향이 짐이 되는 상황과 함께.
6. 1번의 중심 줄기를 끝까지 잇고, 항목 첫 문장은 앞 항목을 받아 시작한다. 같은 내용 반복 금지.
7. 괄호 근거, 영어 키 이름, 테스트 용어 금지.
8. meaning 풀이, headline·patterns, clear_answers 문장, 지시문 문장을 옮겨 적지 않는다.
9. 친구에게 말하듯. "당신"·"저는" 없이 주어 없이, 해설자 말투 금지.
10. 같은 비유·표현·낱말을 되풀이하지 않는다. 비유는 1번에서만, 맞세우기는 핵심을 짚을 때 두 번까지, 장면은 데이터에서 나온 평범한 일상으로 지어내지 않는다.
11. 추측 표현은 문단마다 한 번 정도. 타인 비교·진단명·유형 이름·좋고 나쁨 평가 금지.
12. 존댓말, 2,800자 안팎, 항목 분량을 지킨다.
13. 제목 한 줄과 7개 항목만 쓰고 덧붙이지 않는다.

**테스트로 고정** (`prompt.test.ts`): 태그 순서, 스키마 통과와 patterns·clear_answers, 제목 줄, 7개 항목과 순서, 위 규칙 문구, 사람 중심(D75)과 풀어 쓰기·흐름(D76) 규칙, 응답을 사실 문장으로 바꾸기(이중 부정 방지), 지시문 자체에 "당신"·"아니라"·감성 명사 "결"·괄호 보충이 없음, 6,000자 이하, id·밀리초 없음, 조사 병기·위기 안내 문구 없음.

> 실제 답의 문제와 대응: v3(D33) 타이틀 추측형·용어 노출·단어 혼동 → v4 규칙. v5(D74) "당신" 호칭, 응답 되읽기, 맞세우기 반복, 비유 겹침, 지시문 낭독 → 문체 규칙. v6(D75) "나를 아는 느낌보다 고른 단어를 기술한 느낌" → 사람을 주어로. v7(D76) "더 풀어 쓰고, 나를 잘 설명하고, 항목이 이어지게" → 실제 응답을 행동 근거로, 판단을 이유·행동·속마음으로 풀기, Finn 순서와 중심 줄기.
