## 0. 설계 원칙

1. **짧고 재미있게.** 3분 안팎의 가벼운 자기 이해 활동이다. 1단계는 짧은 5지선다 10문항, 2~5단계는 마음 가는 단어를 여러 개 고르고 덜어내는 방식으로 섞어서 지루하지 않게 한다. 모든 화면은 스크롤 없이 한 화면에 들어온다(D31).
2. **근거는 가볍게, 해석은 정성적으로.** 성격은 검증 척도(Mini-IPIP)의 문항을, 가치는 이론(Schwartz)을 참고한 단어를 쓰되(§2), 결과는 점수가 아니라 기울기와 고른 단어로 정리한다. 검증된 척도가 아니라는 점을 시작 화면, 결과, 프롬프트에 밝힌다.
3. **결과물은 두 가지다(D18, D32).**

   | 결과물 | 구분 | 내용 |
   |---|---|---|
   | 결과 카드 | 필수 | 결과 화면 맨 위 그림 카드 한 장(§5). 상세는 [자세히 보기] |
   | 해석 프롬프트 | 필수 | 복사해서 자기 LLM에 붙여 넣는 글(§6). "# 마음결 · 날짜의 나" 제목 아래 8개 항목으로 답을 받는다 |

   - 그림 프롬프트는 7판에서 뺐다(D32).

   - 다시 보기와 저장 기능은 없다(D22). 복사한 글을 보관하려면 사용자가 메모장 등에 직접 붙여 둔다.
4. **진단하지 않는다.** 병명, 임상 용어, 유형 판정, 타인 비교를 쓰지 않는다. 결과 카드 그림에 이름을 붙이지 않는다. 위기 안내 문구는 넣지 않는다(D6).
5. **서버가 없다.** 모든 계산은 브라우저 안에서 한다. 고른 단어는 어디에도 전송·저장하지 않는다(배포 A 유형).

## 1. 화면 흐름

```
[시작 /] ─▶ [테스트 /test/<단계>] ──────────────────────────▶ [결과 /result]
              1 평소의 나          5지선다 10문항(한 화면에 한 문항)   ├ (0.9초) 고른 단어를 정리하고 있어요
              2 마음이 끌리는 단어   20개 중 5개                     ├ 결과 카드 한 장 (+ [자세히 보기])
              3 끝까지 남길 단어     ②의 5개 중 3개, 누른 순서=순위     ├ [AI에게 해석 받기] → 복사 + AI 버튼
              4 요즘의 나           12개 중 1~3개                   └ [처음부터 다시 하기] (두 번 눌러 실행)
              5 더 키우고 싶은 힘    가치 카드 10장 중 1~2개
```

- **주소(D39)**: 단계마다 `/test/personality` → `/test/values` → `/test/narrow` → `/test/now` → `/test/grow`. 메인 화면의 [시작하기]는 늘 새로 시작한다. 앞 단계를 마치지 않고 뒤 단계 주소로 오면 아직 안 끝낸 첫 단계로 돌려보낸다. 브라우저 뒤로가기로 오갈 수 있다.
- 1단계는 답을 고르면 동그라미가 그려지고 0.28초 뒤 다음 문항으로 넘어간다. 문항 번호 양옆의 "‹ 3 / 10 ›"로 답한 문항 사이를 오갈 수 있고, 내 답이 그대로 보인다(D40).
- 2~5단계 바닥은 [다음] 하나이고, 뒤로 가기는 맨 위 화살표가 맡는다.
- 배경음은 [시작하기]를 누를 때부터 재생하고, 모든 화면 왼쪽 여백 칸의 동그라미 버튼으로 켜고 끈다(D34, D42).
- 2~5단계는 화면 한 장이다. 최소 개수를 채우면 [다음]이 켜지고, 최대 개수를 넘게 누르면 막고 살짝 흔들며 "최대 n개까지"를 0.48초 보여 준다.
- 단어 순서는 시작할 때마다 섞는다(2·5단계). 3단계는 2단계에서 고른 순서 그대로 보여 준다. 2단계에서 뺀 단어는 3단계에서도 빠진다.
- 진행 중 상태는 sessionStorage에만 둔다. 새로고침해도 이어지고, 탭을 닫으면 사라진다.

## 2. 문항, 단어, 근거

| 단계 | 내용 | 근거 |
|---|---|---|
| 1 평소의 나 | **Mini-IPIP 10문항**(`src/data/likert.ts`). 특성(외향성, 친화성, 성실성, 정서 민감성, 개방성)마다 정방향 1개 + 역방향 1개. 선택지 "전혀 아니에요 … 정말 그래요" | Donnellan et al. (2006). IPIP 문항은 퍼블릭 도메인. 20문항 중 10문항 축약은 검증된 판이 아니라서 기울기로만 쓴다(D28) |
| 2·3 가치 단어 | Schwartz 10가지 가치마다 **2개씩, 20개**(`src/data/words.ts`) | Schwartz (1992, 2012). 고르고 덜어내는 방식은 Personal Values Card Sort(Miller et al., 2001) 아이디어 |
| 4 요즘의 나 | 기분 단어 12개 | 점수를 매기지 않는 가벼운 체크. 임상 증상 단어는 쓰지 않는다 |
| 5 더 키우고 싶은 힘 | 10가지 가치 카드 | `src/data/values.ts` |

## 3. 결과 정리 규칙 (`src/lib/analysis/analyze.ts`, 순수 함수)

| 대상 | 규칙 |
|---|---|
| 성격 기울기 | 특성마다 두 문항 평균(역방향은 6 − 응답). 4 이상이면 높은 쪽, 2 이하면 낮은 쪽, 그 사이는 "상황에 따라 달라지는 편". 3에서 1.5 이상 떨어지면 "뚜렷함"(strong) |
| 나의 결(카드) | 높은 쪽·낮은 쪽인 특성 중 3에서 가장 멀리 떨어진 2개 |
| 가치 순서 | 남긴 단어 1·2·3순위에 3·2·1점, 내려놓은 단어에 0.5점. 같은 점수면 더 높은 순위로 남긴 가치, 그다음 정의 순서 |
| 결과 카드 | 1순위로 남긴 단어의 가치(D26) |
| 눈여겨볼 연결(patterns) | ① 남긴 세 단어 중 같은 가치가 2개 이상 ② 남긴 가치 중 서로 반대 방향인 쌍(Schwartz 원형) ③ 키우고 싶은 힘이 남긴 가치에 없음 / 이미 있음 ④ 내려놓은 단어의 가치를 키우고 싶은 힘으로 다시 고름. 최대 4개 |
| 망설임 | 가장 오래 머문 단계, 골랐다가 뺀 단어. 재미로 보는 참고 정보 |

### 5-2. 자세히 보기 (`ResultDetails`)

눈여겨볼 점(patterns), 평소의 나(특성별 기울기), 끝까지 남긴 가치 1~3순위와 정의, 내려놓은 단어, 요즘과 앞으로, 고르는 동안(가장 오래 머문 단계, 골랐다가 뺀 단어), "어떻게 만들었나요?"(한계와 참고 문헌).

### 5-3. 해석 받기 (`AskAi`, D25·D30)

1. [AI에게 해석 받기]를 누르면 해석 프롬프트를 복사한다.
2. 그 버튼 자리에 "복사했어요. 쓰는 AI를 누르고, 대화창에 붙여 넣어 보내 주세요." 한 줄과 ChatGPT · Gemini · Claude 버튼, "휴대폰은 길게 눌러 붙여넣기, PC는 Ctrl+V. [다시 복사]" 한 줄이 나타난다. 큰 버튼은 없애서 바닥 영역이 결과를 가리지 않게 한다.
3. AI 버튼을 누르면 새 창으로 열고, 누르는 순간 해석 프롬프트를 한 번 더 복사한다(그사이 다른 것을 복사했어도 안전).
4. 복사가 막히면 같은 자리에 프롬프트 전문(읽기 전용)과 [텍스트 파일로 저장]을 보여 준다. 인앱 브라우저면 "다른 브라우저로 열기"를 안내한다.

- 복사와 새 탭 열기를 한 번의 탭으로 합치지 않는다. 새 탭으로 초점이 넘어가면 브라우저가 클립보드 쓰기를 막을 수 있다.
- AI 서비스 주소에 프롬프트를 쿼리로 미리 채우지 않는다. 길이가 길어 잘리고 방문 기록에 남는다.

## 6. 해석 프롬프트

### 6-1. 원칙 (D19 유지)

- 복사 전용이다. 사람이 읽기 좋은지보다 LLM이 잘못 읽지 않는지를 기준으로 만든다.
- 데이터를 앞에, 지시를 맨 끝에 둔다. `<result>`, `<about_test>`, `<rules>`, `<answer_format>` 태그로 나눈다.
- 데이터는 들여쓰기 없는 JSON, 키는 영어 snake_case, 값은 한국어.
- 사용자가 자기 이름으로 보내는 1인칭 해요체.
- 단어 id, 밀리초 기록, 섞은 순서, 앱 버전은 넣지 않는다.

### 6-2. 해석용 데이터 `PromptData` (version 3, `buildPromptData`)

### 6-3. 답변 형식 (v4, D33)

- 프롬프트 첫 문장에서 "성격심리와 가치 연구를 잘 아는, 따뜻하지만 솔직한 해설자" 역할을 준다.
- `<about_test>`에서 데이터마다 의미 렌즈를 준다: 평소의 결(기질), 남긴 가치 = 이미 뿌리내린 **확신**, 키우고 싶은 힘 = 지금 바라는 **열망**, 마지막에 내려놓은 단어, 요즘 마음의 날씨. 골랐다가 바로 뺀 단어와 마지막에 내려놓은 단어를 섞지 말라고 적는다.
- 답변 맨 위에 `# 마음결 · 2026년 10월 20일의 나` 제목 한 줄, 그 아래 8개 항목.

| # | 항목 | 분량과 지시 |
|---|---|---|
| 1 | 한 줄 타이틀 | 향하는 방향을 담은 시적인 한 문장. 추측 표현 없이 |
| 2 | 나를 이루는 결 | 기질과 확신이 어떻게 맞물리는지 3~4문장 |
| 3 | 확신과 열망 | 지키는 것과 바라는 것의 차이, 내려놓은 단어 3~4문장 |
| 4 | 세 장면 속의 나 | 혼자 / 사람들과 / 일할 때 굵은 소제목, 장면마다 2~3문장 + 할 법한 말 한 줄. 혼자: 힘을 얻는·지치는 방식, 사람들: 잘 맞는 사람·불편한 상황, 일: 강점·스트레스 환경 |
| 5 | 조심하면 좋을 점 | 빠지기 쉬운 패턴 하나 + 스스로 지치게 하는 방식 하나, 예시와 함께 3~4문장 |
| 6 | 요즘의 나 | 마음의 날씨 2문장, 평가 없이 |
| 7 | 이번 주 작은 한 걸음 | 10분 안에 해 볼 행동 2개 |
| 8 | 응원 한마디 | 2~3문장 |

규칙 7가지(`PROMPT_RULES`):
1. 데이터만 근거로 쓴다.
2. 서로 다른 데이터를 잇고(기질과 확신, 확신과 열망), 누구에게나 맞는 일반론을 쓰지 않는다.
3. 괄호 근거, 영어 키 이름, 테스트 용어 나열을 하지 않는다.
4. 같은 비유를 되풀이하지 않는다. 카드 그림은 1번에서만 쓴다.
5. 추측 표현은 문단마다 한 번 정도만 쓴다. 타인 비교·진단명·유형 이름·좋고 나쁨 평가를 쓰지 않는다.
6. 처음부터 끝까지 존댓말로 쓰고, 전체 2,000자 안팎을 지킨다.
7. 제목 한 줄과 8개 항목만 쓰고 덧붙임을 하지 않는다.

**테스트로 고정** (`prompt.test.ts`): 태그 순서, 스키마 통과와 patterns, 제목 줄, 8개 항목과 7·8번 제목, 세 장면 소항목, 위 규칙 문구, 4,000자 이하, id·밀리초 없음, 조사 병기·위기 안내 문구 없음.

> 사용자가 v3로 받은 Claude 답변의 문제(D33): 타이틀까지 추측형, 문장마다 "~일 수 있어요", "뚜렷하게 기울어"·"남긴 가치에 없어서" 같은 용어·단서 문장 노출, 골랐다 뺀 단어와 내려놓은 단어 혼동, 관계·일 장면이 한두 문장. v4 규칙은 이를 하나씩 막는다.
